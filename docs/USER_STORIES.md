# Hollow — User stories (approved, D37)

Derived from GDD §15 (journey + acceptance table) and the section named per task.
Approved by the user (D37). Their status after the build is reviewed in `docs/RELEASE_NOTES.md`.
Acceptance criteria marked (human) need a human playtest and will never be marked passed by me.

| Task | Story | Acceptance criteria (testable) |
|---|---|---|
| T00 Foundation | As a programmer, I want a state machine, two clocks and an input router so that every system pauses and receives input consistently. | Every legal/illegal state transition is unit-tested; active-second timers freeze while real-time UI keeps running; a UI click is never delivered to the world. |
| T01 Data layer | As a designer, I want every gameplay number in one versioned profile so that I can tune without code. | Calculator reproduces 226/238/31/269, 322/340/39/379, 446/454/43/497, 994/1032/113/1145, XP 1116/1990/3246, pre-boss coins 804/1534/2614; incomplete weapon levels are flagged; ranged cap > total cap is rejected. |
| T02 Player | As a player, I want movement, aim and dash that never wait for animation so that I feel in control (§15 "Responsive control"). | Diagonal speed = straight speed; dash 3 u / 0.18 s from data; dash never crosses a wall; dash hits each enemy once; post-hit invulnerability never blocks input. (human: "feels responsive") |
| T03 Guns | As a player, I want guns that reload predictably and keep their state when I swap so that I can manage fire under pressure. | Reload cancel/restart, magazine kept across swap, shotgun falloff, two-target penetration, skill modifier applied exactly once, 0.45 s reload floor — all unit-tested. |
| T04 Melee | As a player, I want melee swings with a visible arc so that I can see what I will hit. | One swing damages each target in arc once; reach/arc boundaries; knockback; movement during swings; only the energy blade ignores frontal armour. |
| T05 Feel | As a player, I want every shot and hit to give layered feedback so that combat feels powerful without hiding danger. | Pistol, SMG, shotgun show all applicable layers; effect budget caps particles/decals/numbers; telegraphs drawn above effects; 40-enemy stress scene frame rate measured and reported. (human: "feels good") |
| T06 Enemy framework | As a player, I want every enemy attack to be warned first so that I can react instead of guess. | A1 loop spawn→chase→bite→die→coins→XP with table rewards; armour test front/side/rear; a telegraph precedes every damaging attack (automated check). |
| T07 20 enemies | As a player, I want each enemy type to look and attack differently so that I can prioritise targets. | Test scene per enemy; producer pool tests (kill early / late / never): total paid equals the fixed pool once everything is dead and never exceeds it. |
| T08 Coins, XP, skills | As a player, I want to see before/after values on each skill card so that I understand my upgrade (§15 "Understand upgrades"). | Threshold sequence 40/70/100…, overflow carry, chained thresholds, no duplicates/maxed skills, +20 max & current health, coin lifetime freeze rules; pending card serialises. (human: can explain a change from the card) |
| T09 Companion | As a player, I want to see when and why my companion is in danger so that I can rescue it (§15 "Rescue the companion"). | Attacker cap 3; companion death fails the encounter in phases 1–2 and the failure screen names the cause; freezes during XP pause; phase-2 entry sets health to the new max. (human: understands warnings) |
| T10 Waves | As a player, I want waves to build up readably and start gently after each phase change so that I am challenged but not overwhelmed. | Batch rounding preserves totals; cap waiting; safe-distance spawning; support cap 2; tutorial gating; wave-end condition with producers; bot run of all 15 waves never sticks. |
| T11 Shop | As a player, I want to shop quickly without pausing and without accidental shots (§15 "Live shopping"). | Purchases are atomic; stock refreshes only per wave/boss prep; tutorial gating; clicking Buy never fires a weapon (automated input test). |
| T12 Items | As a player, I want to equip, aim and cancel items safely so that I never waste one by mistake. | 0.5 s use gap; every cancel path; invalid use consumes nothing; mine cap 4 and removal on phase change; EMP never stuns humans; shield never stacks. |
| T13 Bosses | As a player, I want bosses with readable patterns and a calm preparation step so that each phase ends in a fair climax. | Threshold groups fire once across heal and load; reward pool conserved for quick and slow kills; hazards cleared at boss death; preparation flow shop→Ready→scene and direct start. |
| T14 Story | As a player, I want short skippable scenes that show the human losing purpose so that I understand "Hollow" (§15 "Understand Hollow"). | Three transitions and the ending playable and skippable on retry; dialogue never blocks combat input outside designated scenes. (human: theme recognised without explanation) |
| T15 HUD & screens | As a player, I want every screen to have a clear way forward so that I never get stuck in a menu. | Every screen reachable, no dead ends, no click leaks into the world; layouts checked at 1920×1080, 1600×900, 1280×720. |
| T16 Arena | As a player, I want each phase's arena to change its cover and paths so that each faction plays differently. | Screenshots of the three states; navigation check that every spawn zone leaves an escape route; no character inside a new obstacle at transition. |
| T17 Saves | As a player, I want each slot to restore the exact moment after a full exit without touching other slots (§15 "Exact continuation"). | Mid-fight save → quit → relaunch → load gives an identical state hash, then identical outcomes for N frames with a fixed seed; slot B untouched when slot A changes; atomic write; failures shown. |
| T18 Panel & telemetry | As a designer, I want to change any number at runtime and log runs so that I can balance from observations. | Every gameplay number reachable in the panel; repo-wide search for hard-coded gameplay constants reported; F10 dev panel absent from release builds; telemetry file written per run. |
| T19 Audio | As a player, I want every important event to have a sound that never masks attack warnings. | Every listed cue plays; ducking never hides telegraph sounds; CREDITS.md complete; total audio size reported. |
| T20 Tutorial & readability | As a new player, I want to learn movement, firing and buying without being told (§15 "Understand the start"). | Checklist of the 7 §15 criteria with pass / fail / needs human test; human-perception items never marked passed. |
| T21 Stress & bot | As a programmer, I want a scripted full run and a worst-case stress test so that soft-locks and performance problems show up before the jam ends. | Written report: frame rate, GC alloc per frame, memory on this machine; anything not measured labelled "not measured". |
| T22 Build | As the team, I want a clean Windows build and honest release notes so that we know exactly what works. | Clean build, full test suite run, release notes listing works / placeholder / untested / open questions / designer to-do. |
